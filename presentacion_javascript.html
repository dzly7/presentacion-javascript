¿Qué es JavaScript?

Es el lenguaje de programación de la web. Todo lo interactivo que ves en un sitio web — menús que se despliegan, formularios que se validan, notificaciones, animaciones, chats en tiempo real — es JavaScript trabajando detrás de escena.

🏗️

Si una página web fuera una casa:
HTML = la estructura (paredes, techo)
CSS = la decoración (pintura, muebles)
JavaScript = la electricidad y plomería
(lo que hace que todo funcione) 

// Ejemplo: un botón que saluda

const boton = document.querySelector('#saludar');

boton.addEventListener('click', () => {
  alert('¡Hola! 👋 Esto es JavaScript');
});

// Con solo estas 3 líneas, un botón
// de tu página ya es interactivomi primer código js

Anatomía de la Sintaxis: JS vs HTML & CSS

¿Cómo se diferencian en Sintaxis?

HTML (Etiquetas)
<button id="btn">Clic</button>
Define la estructura y los elementos.
CSS (Reglas y Propiedades)
#btn { background: red; }
Define colores, tamaños y diseño visual.
JS (Variables, Funciones y Métodos)
const btn = document.querySelector('#btn');
Define acciones e interactividad.

Glosario de Palabras Clave en JS

  • const / let: Sirven para declarar variables (guardar datos en memoria). const no cambia, let sí.
  • function: Define un bloque de código reutilizable que realiza una acción.
  • document: Objeto global que representa toda tu página web en memoria.
  • querySelector(): Método que busca y selecciona un elemento HTML por su ID o clase de CSS.
  • addEventListener(): "Escuchador" que ejecuta código cuando ocurre un evento (clic, tecla, etc.).

Cuando escribes JavaScript, el navegador lo convierte en instrucciones que la computadora entiende:

↓
Motor V8 (lo traduce)

V8 es el motor de Chrome y Node.js, creado por Google. Es tan rápido que JavaScript puede competir con lenguajes como C++.

El Event Loop: cómo hace varias cosas a la vez

La pila de tareas (Call Stack)

JavaScript ejecuta las tareas una por una, como una pila de platos: el último plato que pones es el primero que lavas.

Pero... ¿y las tareas lentas?

Cuando algo tarda (cargar datos, un temporizador), JS lo delega al navegador y sigue trabajando. Cuando termina, el resultado vuelve a la fila.

🔁 El Event Loop es el mecanismo que revisa: "¿Ya terminaste? Ok, te paso al frente."

// Veamos cómo funciona:

console.log('1. Primero');

setTimeout(() => {
  console.log('2. Después de 2 seg');
}, 2000);

console.log('3. ¡Pero yo salgo antes!');

// Resultado:
// 1. Primero
// 3. ¡Pero yo salgo antes!
// 2. Después de 2 seg  (espera su turno)

// JS no se "congela" esperando
// los 2 segundos. Sigue trabajando
// y cuando el timer termina,
// el resultado entra por el Event Looppruébalo en consola

El DOM: así JavaScript controla lo que ves

El DOM es la representación viva de la página en memoria. JavaScript puede leer, cambiar, crear y eliminar cualquier elemento.

// Cambiar el color de un título
const titulo = document.querySelector('h1');
titulo.style.color = '#F7DF1E';

// Cambiar el texto
titulo.textContent = '¡Modificado con JS!';

// Crear un elemento nuevo
const parrafo = document.createElement('p');
parrafo.textContent = 'Yo no existía en el HTML 👻';
document.body.appendChild(parrafo);dom

Los eventos: reaccionar al usuario

Cada acción del usuario (click, tecla, scroll) genera un evento que JavaScript puede escuchar.

// Escuchar un click

  alert('¡Hiciste click!');

// Escuchar el teclado

  console.log(`Presionaste: ${e.key}`);

Traer datos de internet con Async/Await

Cuando una app necesita datos de un servidor (tu feed de Instagram, resultados de búsqueda, etc.), JavaScript los pide sin congelar la página.

📱

Es como pedir comida por app:
Haces el pedido → sigues con tu vida →
te avisan cuando llega

No te quedas parado en la puerta esperando. 

// Ejemplo real: traer datos de GitHub

async function buscarUsuario(nombre) {
  // "await" = espera el resultado
  // pero NO congela la página
  const respuesta = await fetch(
    `https://api.github.com/users/${nombre}`
  );

  const datos = await respuesta.json();

  console.log(datos.name);
  console.log(datos.public_repos + ' repos');
}

buscarUsuario('torvalds');
// → "Linus Torvalds"
// → "7 repos"fetch api

TypeScript: JavaScript que te avisa antes de equivocarte

❌ JavaScript: el error aparece AL EJECUTAR
function saludar(usuario) {
  return 'Hola, ' + usuario.nombre;
}

// Nos equivocamos y pasamos un número
saludar(42);
// 💥 Error en producción:
// "Cannot read property 'nombre'"
// El usuario ya vio el error 😱
✅ TypeScript: el error aparece MIENTRAS ESCRIBES
type Usuario = {
  nombre: string;
  edad: number;
};

function saludar(usuario: Usuario) {
  return 'Hola, ' + usuario.nombre;
}

saludar(42);
// ❌ Tu editor te marca el error
// ANTES de ejecutar el código
// "Se esperaba un Usuario, no un número"

TypeScript se convierte a JavaScript puro → funciona en todos lados. Hoy lo usa el 78% de los desarrolladores profesionales.

Las cosas raras de JavaScript 🤯

// JavaScript tiene "bugs" históricos
// que nunca se corrigieron para no
// romper millones de páginas web

typeof null        // "object" 🤯
                     // (bug desde 1995)

NaN === NaN        // false
                     // (NaN no es igual a sí mismo)

0.1 + 0.2           // 0.30000000000000004
                     // (así funcionan los decimales
                     //  en binario, no es solo de JS)

[] == ![]          // true 🤯🤯🤯

'b' + 'a' + + 'a' + 'a'
                     // "baNaNa" 🍌💡 pruébalos

¿Por qué pasa esto?

  • JavaScript intenta "adivinar" qué querías hacer cuando mezclas tipos de datos
  • A esto se le llama coerción de tipos — convierte automáticamente números a texto (y viceversa)
  • Fue diseñado para ser "amigable" con principiantes... pero a veces se pasa 😅

✅ La solución es simple:

  • Usar === en vez de == (comparación estricta)
  • Usar TypeScript para que te avise de errores
  • Estos quirks son divertidos pero rara vez te afectan en la vida real
